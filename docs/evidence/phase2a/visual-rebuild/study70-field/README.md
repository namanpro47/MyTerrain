# Study70 — crop volume instead of isolated row plants

**Rendered: crop massing improves, but the construction is not accepted or adopted.** Continuing from `dc3a2e8` on separate branch `codex/visual-field70`; `codex/visual-study20` remains frozen for the combined-release owner. Main inspected at `13a15a4`. TN-02/09/12; [operative goal](../../../../PHASE_2A_GOAL.md).

The foreground remains dominated by small plants separated by exposed raised-soil ridges. The hypothesis is a mature planted volume with broad access lanes: preserve real source plant silhouette and depth through spatial slices, instead of a ground-only texture, a closed canopy sheet, or another density/tint change to the existing vegetable rows. Test one actual West-field parcel before considering full-map work. Source geography, annual state, camera and surrounding scene remain controls.

The existing CC0 Quaternius-derived `FieldWheat` mesh is the source. Offline rendering forms a periodic6×6×2m volume, with16 slices on each of3axes. The runtime uses terrain-conforming planes and a parcel/source-cover/route eligibility mask. This is rasterization of licensed geometry, not image generation. The dominant view axis selects the slice stack; the first implementation is diagnostic and may reveal stepping or axis changes. Alpha filtering, geometric transitions, shadows, motion and browser costs are unresolved. No claim of a new observed crop species or yield.

Technical context: [NVIDIA GPU Gems39](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-39-volume-rendering-techniques) describes texture-based volume rendering with proxy slices and sampling artifacts; this experiment uses cutout plant surfaces rather than its translucent volume integration. [Unity Texture2DArray](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/texture2darray/ctor) documents the array container. Neither source establishes visual quality or Web performance for this experiment.

Prepared sources: [bake shader](VolumeBake.shader.txt), [bake script](bake.cs.txt), [runtime shader](VolumeField.shader.txt), [application](apply.cs.txt), [camera setup](setup.cs.txt), [close camera](close.cs.txt), [capture](capture.cs.txt). Initial [normal control](control-normal.png) and [close control](control-close.png) use the retained study65 runtime. The bake succeeds:324 source instances including periodic overlap,306triangles per source mesh,48×256² slices and9mips, approximately16MiB raw GPU texture data with mipmaps. [Bake receipt](bake.json). The source model is the existing CC0 Quaternius-derived mesh; these textures are engine renders, not generated artwork. The source height envelope is2m, with actual grain below it. Native normals were reduced to a weak baked value modulation and the runtime currently lights the entire volume as upward-facing; this simplification is a material remaining weakness.

- **Color filtering correction:** [close](filtered-close.png), [30-degree edge view](filtered-edge.png). Unweighting RGB by sampled alpha preserves source color at filtered edges. Crop stems and lane depth are clearer. The hard camera-axis switch remains undesirable, so the next version combines all three opaque stacks instead of switching. - **Distance treatment:** side stacks fade when their2m envelope becomes subpixel, while horizontal slices remain. [Wide](filtered-wide.png). Crosshatching decreases, but normal mip filtering loses crop coverage and exposes too much brown floor. Not accepted.
- **Native import treatment:** [Unity's coverage-preserving mipmaps](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/textureimporter/mipmapspreservecoverage) and [transparent-color dilation](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityeditor/textureimportersettings) are applied to each slice at alpha cutoff.4; authored mips are copied into a second array without regeneration. [Import result](coverage-result.json), [script](coverage.cs.txt). This supersedes manual RGB unweighting in the final experimental shader. [Normal](coverage-normal.png), [close](coverage-close.png), [wide](coverage-wide.png). Coverage holds, but the aggregated canopy becomes too bright and flat, with abrupt lane edges. **Reject this as a finished field treatment.** It does not meet the reference bar.

**Keep only the construction hypothesis for the next test.** Broad crop massing is a visible improvement at normal scale, but current shading/coverage does not preserve convincing plant form across distances. Next technical question: can source-derived normals/depth and a coherent distance representation preserve the grain heads and rooted edges without granular noise or an opaque foam-like canopy? This must be answered in actual normal/close/wide output before integrating runtime code. Do not return to per-pixel axis switching, density/tint tuning, or simply declare the smoother coverage image accepted. Landscape composition, woodland forms, transformations, full HUD, motion and Chrome delivery still remain separate gate failures.
