# Study70 — crop volume instead of isolated row plants

**Prepared; not yet rendered or adopted.** Continuing from `dc3a2e8` on separate branch `codex/visual-field70`; `codex/visual-study20` remains frozen for the combined-release owner. Main inspected at `13a15a4`. TN-02/09/12; [operative goal](../../../../PHASE_2A_GOAL.md).

The foreground remains dominated by small plants separated by exposed raised-soil ridges. The hypothesis is a mature planted volume with broad access lanes: preserve real source plant silhouette and depth through spatial slices, instead of a ground-only texture, a closed canopy sheet, or another density/tint change to the existing vegetable rows. Test one actual West-field parcel before considering full-map work. Source geography, annual state, camera and surrounding scene remain controls.

The existing CC0 Quaternius-derived `FieldWheat` mesh is the source. Offline rendering forms a periodic6×6×2m volume, with16 slices on each of3axes. The runtime uses terrain-conforming planes and a parcel/source-cover/route eligibility mask. This is rasterization of licensed geometry, not image generation. The dominant view axis selects the slice stack; the first implementation is diagnostic and may reveal stepping or axis changes. Alpha filtering, geometric transitions, shadows, motion and browser costs are unresolved. No claim of a new observed crop species or yield.

Technical context: [NVIDIA GPU Gems39](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-39-volume-rendering-techniques) describes texture-based volume rendering with proxy slices and sampling artifacts; this experiment uses cutout plant surfaces rather than its translucent volume integration. [Unity Texture2DArray](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/texture2darray/ctor) documents the array container. Neither source establishes visual quality or Web performance for this experiment.
