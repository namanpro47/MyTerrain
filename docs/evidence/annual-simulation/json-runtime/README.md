# Numeric JSON runtime compatibility diagnostic

The combined release owner ran the existing four-decade helper in Unity 6000.6.6f1. The first numeric definition failed its exact identity check: expected `6e9235f19fc4d2cf321b24351fdefd3c3e34bfc34fd998931910f4c53a53b95a`, actual `7fb05b1e92e991f9efed15702c02bd797974201df86051027945699abda17366`. The [actual Unity probe](unity-hash-probe.json) and [parsed definition](unity-parsed-definition.json) preserve that failure. Several double values change by one representable step through JsonUtility, for example action 5 vegetatedFraction `0.024625792811839322` becomes `0.02462579281183932`. Float formatting expansion and null-to-empty strings are separate, expected differences.

A bounded offline probe uses the **same installed Unity ARM64 Mono executable**, the frozen `632c159` model compiled for .NET Standard 2.1, and the already-installed Unity Newtonsoft JSON **3.2.2** package. It passes **60 assertions across four complete ten-year fixtures**: baseline, public repair, repair debt, and six financed data centers. All four original definition hashes, all 40 accepted transition hashes, cash/arrears, and both definition and complete snapshot JSON round trips match. [Output](mono-result.txt), [exact program](ModelProbe.cs.txt), [input and binary hashes](identity.json).

The client owner is adapting only the inactive numeric store to this library, with an explicit package dependency and DTO preservation for IL2CPP. Existing schema-2 gameplay and its JsonUtility persistence remain unchanged. This diagnostic **does not** certify an actual Unity player, browser, linker, IndexedDB storage or numeric activation. Those checks remain required. No values, accepted hashes or simulation rules were rounded to make the test pass.

## Reproduction

At frozen source 632c159, run `tests/annual-simulation/Terra.AnnualSimulationChecks.csproj` to regenerate `Builds/AnnualSimulation/UnityVectors`. Compile Core, Contracts and Simulation sources as a .NET Standard 2.1 library with C# 9. Copy that library as `Portable.dll` and the installed package's `Runtime/Newtonsoft.Json.dll` beside the probe. Use Unity's `Contents/Resources/Scripting/MonoBleedingEdge/bin/mono` and bundled `lib/mono/4.5/mcs.exe` to compile the probe, referencing both libraries and `lib/mono/4.5/Facades/netstandard.dll`. Run the executable from the repository root. The program fails immediately on any mismatch and prints PASS only after all assertions succeed.
